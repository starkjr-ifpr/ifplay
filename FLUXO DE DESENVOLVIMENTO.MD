# IFPlay — Fluxo de Desenvolvimento

Este documento explica como as tasks do IFPlay devem ser realizadas.

O objetivo é criar um fluxo simples e organizado para que todos os integrantes consigam:

* escolher uma task;
* trabalhar em uma branch própria;
* desenvolver sem alterar diretamente a `main`;
* registrar o trabalho no GitHub;
* abrir um Pull Request;
* receber revisão;
* corrigir possíveis problemas;
* ter o código aprovado e integrado ao projeto.

> **Regra principal: ninguém deve desenvolver diretamente na `main`.**

---

# 1. Como funciona o fluxo

Sempre que você for realizar uma task, siga esta sequência:

```text
Issue
  ↓
Assumir a task
  ↓
Comentar na Issue
  ↓
Criar Branch
  ↓
Desenvolver
  ↓
Testar
  ↓
Commit
  ↓
Push
  ↓
Pull Request
  ↓
Code Review
  ↓
Aprovação do Tech Lead
  ↓
Merge
```

Esse fluxo deve ser seguido para todas as tasks.

---

# 2. Encontrando uma task

As tasks do projeto serão cadastradas como **Issues no GitHub**.

Entre na aba:

```text
GitHub
→ Issues
```

Procure uma task que você tenha interesse em realizar.

Leia toda a descrição da Issue antes de começar.

Verifique:

* objetivo;
* requisitos;
* critérios de conclusão;
* dependências;
* estimativa de horas;
* possíveis observações.

---

# 3. Assumindo uma Issue

Antes de começar a trabalhar, você deve se colocar como responsável pela Issue.

Na Issue, procure a opção:

```text
Assignees
```

e adicione seu usuário.

Isso informa para toda a equipe:

> "Esta task está sendo realizada por mim."

---

# 4. Comentar na Issue

Depois de se colocar como responsável, faça um comentário informando que você vai realizar a task.

Exemplo:

```text
Vou assumir esta task e começar o desenvolvimento.
```

Se quiser, pode informar também a branch que será criada:

```text
Vou
```
